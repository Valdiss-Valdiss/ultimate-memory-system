# AGENTS.md — инструкция для ИИ-агента

> Это главный файл для ИИ-агента (Claude Code / Codex / opencode / Cursor / любой другой).
> Ваша задача: развернуть и поддерживать Memory System на машине пользователя.
> Прочти сначала: [README.md](README.md) → [ARCHITECTURE.md](ARCHITECTURE.md) → [SECURITY.md](SECURITY.md).

## Главный принцип: цель — состояние, а не шаги

Не выполняй «шаги установщика». Приводи систему к **целевому состоянию** (оно описано
в `ARCHITECTURE.md` и проверяется скриптами `validate/`). Алгоритм работы:

```
1. Запусти validate (validate/validate_vps.py и/или validate_pc.py)
2. Прочитай, что красное
3. Найди в runbooks/ раздел по этому пункту → выполни рекомендацию
4. Повтори validate → пока всё зелёное
```

Никогда не выдумывай команды, если не уверен — в рунбуках есть проверенные рецепты
с указанием рисков и откатов.

## Порядок чтения (обязателен для новой сессии)

1. `STATUS.md` (в корне пользовательской копии) — текущее состояние инстанса
   (если файла нет — создай из `STATUS-TEMPLATE.md`).
2. `ARCHITECTURE.md` — что есть что.
3. `SECURITY.md` — что нельзя делать с ключами и данными.
4. Релевантные рунбуки из `docs/runbooks/` под текущую задачу.

## Критические правила (нарушение = потеря данных пользователя)

1. **E2E-парольная фраза vault НИКОГДА не хранится на сервере.** Она вводится только
   на устройствах пользователя (ПК, телефон). Если видишь её где-то на сервере — удали и
   зафиксируй инцидент в STATUS.md.
2. **Telegram-клиент строго один.** Одновременно может работать только ОДИН процесс
   с user-сессией (pc_catchup ИЛИ бэкфилл ИЛИ ренеймер). Перед запуском одного —
   проверь, что другой не запущен. Нарушение даёт `sqlite database is locked` и падения.
3. **Секреты никогда не печатаются** (значения .env, токены, passphrase). Проверка
   наличия — по именам переменных, не по значениям.
4. **Перед опасными операциями — снапшот.** Хостинг-снапшот ВМ живёт ~1 сутки.
   Любое массовое изменение (миграции, переименования, пересборка зеркала) — только
   после свежего снапшота.
5. **Не удаляй данные пользователя без подтверждения.** Удаления в vault propagated
   через sync на все устройства. Массовые удаления — запрет без явного GO.
6. **ПК пользователя не технаря** — не изменяй системные настройки (питание, сеть,
   файлы вне рабочей папки) без явного подтверждения юзера, кроме случаев, описанных
   в `docs/runbooks/runbook-windows-quirks.md` (там перечислено, что можно и почему).
7. **Obsidian-конвенции**: заметки — SKILL v2 frontmatter, уникальность имён по
   casefold; удаления через корзину; переименования — только при закрытом sync'е
   или по зеркалу (см. runbook-deletion-waves.md).

## Дисциплина статуса

- Каждая сессия агента **обязана** обновлять `STATUS.md`: дата сверху, раздел
  «Последние изменения», «Текущее состояние», «Что дальше».
- Существенные решения (выбор технологии, порядок операций) — в `docs/decisions.md`
  строкой: решение / почему / отвергнутые альтернативы.
- Устаревшие документы — переносить в `docs/history/`, не оставлять в корне.

## Запуск и стоп

- Серверные компоненты: `docker compose` в `vps/` (см. `vps/README.md`).
- ПК-конвейер: часовая запланированная задача запускает `catchup.bat` (цепочка:
  pc_catchup → triage → floodguard-рестарт бэкфиллов → note_renamer).
  Установка задачи — см. `pc-scripts/README.md`.
- Запрет: не запускать несколько python-процессов с Telegram-сессией одновременно.

## Структура рунбуков (docs/runbooks/)

| Рунбук | Когда читать |
|---|---|
| `runbook-00-overview.md` | Первый раз: как всё связано, порядок внедрения |
| `runbook-vps-setup.md` | Развёртывание/восстановление серверной части |
| `runbook-obsidian-livesync.md` | Плагин LiveSync, E2E-шифрование, настройка устройств |
| `runbook-telegram-import.md` | Конвейер Telegram → заметки (оба направления) |
| `runbook-deletion-waves.md` | Диагностика/лечение массовых удалений, дедуп, mirror-last |
| `runbook-snapshots.md` | Снапшоты ВМ: когда, как, восстановление |
| `runbook-ssh-hygiene.md` | SSH-доступ, rate-limit, ключи, netguard |
| `runbook-windows-quirks.md` | Windows-специфика: питание/сон, wscript, stdout, планировщик |
| `runbook-troubleshooting.md` | Быстрые рецепты по симптомам |

## Проверенные рецепты (не выдумывай свои)

Все команды в рунбуках проверены вживую на проде. Если твоя ситуация отличается —
сначала перечитай рунбук; если пути нет — сделай предложение пользователю, получи
подтверждение, зафиксируй в decisions.md.
