# memory-MCP — память для ИИ-агентов

Сервер [MCP](https://modelcontextprotocol.io) поверх расшифрованного зеркала vault. Даёт любому
ИИ-агенту (opencode, Hermes, Claude, Cursor…) поиск и чтение **всех** заметок, а запись —
**только в свою зону** `Inbox/<агент>/`. Один образ — несколько экземпляров: по одному на агента.

## Инструменты

| Инструмент | Доступ | Что делает |
|---|---|---|
| `find_notes(query, top=20, fresh=False)` | чтение | **Главный.** Гибридный поиск → готовый ответ `answer_markdown`: до 20 заметок, у каждой «[имя заметки](пост в Telegram) · [открыть в Obsidian](…)» + описание 2–4 строки; в конце ссылка на полный список и подсказка «обобщи». Агент пересылает его пользователю дословно |
| `search_digest(path)` | чтение + запись в свою зону | «Обобщи»: сервер сам читает **все** заметки из заметки поиска (сильная модель, два шага: отбор → чтение целиком) и пишет обобщение с номерами источников; дописывает `## Обобщение` в заметку поиска |
| `semantic_search(query, folder, channel, limit, fresh)` | чтение | Тот же гибридный поиск, «сырой» список с оценками — для своего анализа агента |
| `search_notes(query, limit)` | чтение | Поиск по точным словам/именам/ID |
| `read_note`, `list_notes`, `get_vault_stats` | чтение | Чтение заметки, список, статистика |
| `create_inbox_note`, `append_to_inbox_note`, `edit_note`, `move_note`, `delete_note` | запись **только** в `INBOX_PREFIX` | Удаление мягкое — в `Inbox/<агент>/Trash/` |

Каждый поиск создаёт **заметку поиска** `Inbox/<агент>/Search/<дата>-<тема>.md` (таблица
`# | score | date | folder | title | path` с полным списком, даже при 0 результатах). Служебные
папки `Search/`, `Status/`, `Trash/` в индекс не попадают.

## Как устроен поиск (кратко)

1. **Две формулировки запроса**: слова пользователя + расширение одной дешёвой LLM на сервере
   (синонимы, английские эквиваленты, названия сервисов) — одинаково для всех агентов, с кэшем.
   Модель недоступна → поиск идёт по словам пользователя, без ошибки.
2. **Два индекса**: смысловой (Qdrant, эмбеддинги e5 из TEI; куски ~1300 симв.) и словесный BM25
   (Qdrant sparse, русская/английская морфология, заметка целиком = одна точка).
3. **Слияние**: 2 формулировки × 2 индекса = 4 списка → RRF (k=60) → до 100 заметок.

Подробности, замеры и как проверять правки — `docs/runbooks/runbook-search.md`.

## Транспорты

Один порт (8765), два протокола: SSE (`GET /sse` + `POST /messages`) и Streamable HTTP
(`POST /mcp`). `GET /health` — для мониторинга.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `VAULT_PATH` | `/vault` | Зеркало vault внутри контейнера |
| `INBOX_PREFIX` | `Inbox/AI/` | Зона записи этого экземпляра |
| `AUDIT_LOG` | `/var/log/memory-mcp/audit.log` | Журнал всех операций (JSON lines) |
| `QDRANT_URL`, `QDRANT_API_KEY` (или файл `QDRANT_KEY_FILE`) | `http://qdrant:6333` | Qdrant |
| `TEI_URL` | `http://memory_tei:80` | Сервер эмбеддингов (та же модель, что у индексатора!) |
| `QDRANT_COLLECTION` | — | Смысловая коллекция (как у `memory_indexer`) |
| `QDRANT_BM25_COLLECTION` | `vault_bm25` | Словесная коллекция (пишет `bm25_indexer`) |
| `EXPAND_URL`, `EXPAND_MODELS`, `EXPAND_KEY_FILE`, `EXPAND_TIMEOUT` | — / — / `/llm-key` / 8 с | Расширение запроса (OpenAI-совместимый endpoint; ключи — файл, по одному в строке) |
| `SUMMARY_MODEL`, `SUMMARY_EFFORT` | — | Модель для «обобщи» |
| `OBSIDIAN_VAULT_NAME`, `OBSIDIAN_BRIDGE` | — | Ссылки «открыть в Obsidian» (`obsidian://` и https-переходник) |

## Безопасность

- Наружу — **только** через реверс-прокси с токеном (`vps/caddy/memory-mcp.caddy.example`).
  Без авторизации сервер = чтение всего вашего vault любым сканером интернета.
- Запись ограничена кодом (`src/security.py`: путь внутри vault и внутри `INBOX_PREFIX`, защита
  от `..`) — плюс отдельный экземпляр на каждого агента.
- Тесты: `pytest tests/` (обход путей, зоны записи, мягкое удаление).

## Индексатор BM25

`python -m src.bm25_indexer` (сервис `bm25` в `vps/docker-compose.yml`): раз в 5 минут
переиндексирует изменившиеся заметки, удалённые — вычищает.
