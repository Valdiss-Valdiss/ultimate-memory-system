# Runbook — память для ИИ-агентов (memory-MCP)

Цель: любой ИИ-агент пользователя ищет и читает заметки, пишет только в свою зону, а снаружи
к серверу не может подключиться никто без токена.

## Целевое состояние (проверяет `validate/validate_vps.py`)
- контейнеры `memory_mcp` и `memory_bm25` запущены; `GET http://127.0.0.1:8765/health` → `{"status":"ok"}`;
- в Qdrant есть смысловая коллекция (`QDRANT_COLLECTION`) и словесная (`QDRANT_BM25_COLLECTION`), число точек растёт вместе с vault;
- снаружи: запрос без токена → 401, с токеном → работает;
- каждый агент — свой экземпляр сервера со своей зоной записи `Inbox/<агент>/`.

## 1. Развернуть
1. В `vps/.env` заполнить блок «Память для ИИ-агентов» (см. `.env.example`).
2. Ключи LLM для расширения запроса и «обобщи» — в `vps/secrets/mcp-llm-key` (по одному в строке, `chmod 600`). Не в `.env`, не в git.
3. `docker compose up -d --build mcp bm25` (из `vps/`). Индекс BM25 строится сам за несколько минут.
4. Проверка: `curl -s http://127.0.0.1:8765/health`.

Модель эмбеддингов у `tei`, `indexer` и `mcp` должна быть **одна и та же**: векторы запроса и
заметок сравнимы только внутри одной модели. Если тот же TEI используют другие ваши проекты —
не меняйте в нём модель (их векторы тихо перестанут находиться: длина векторов та же, ошибок не будет).

## 2. Открыть наружу (только с токеном)
1. Сгенерировать токен: `openssl rand -hex 32`.
2. Сниппет `mcp-auth.snippet` (`chmod 600`, вне git) — см. шапку `vps/caddy/memory-mcp.caddy.example`.
3. Подключить сайт из `memory-mcp.caddy.example` в Caddy, перезагрузить Caddy.
4. Проверка: `curl -i https://mcp.YOUR-DOMAIN/sse` → 401; с `-H "Authorization: Bearer <токен>"` → поток SSE.
5. (Ссылки «открыть в Obsidian») положить `vps/caddy/obsidian-open.html` в каталог статики Caddy
   и указать в `.env` `OBSIDIAN_BRIDGE=https://mcp.YOUR-DOMAIN/o?`.

Почему не IP-whitelist: у пользователя часто меняется IP (VPN, мобильная сеть), облачные агенты
ходят с чужих IP. Почему токен на прокси, а не в коде сервера: не нужно пересобирать образ, все
экземпляры защищены одинаково, токен не попадает в логи сервера.

## 3. Подключение агентов
- **opencode (ПК)**: в `opencode.json` — локальный MCP через `mcp-remote` с заголовком из файла
  (токен не в конфиге):
  ```json
  "memory": { "type": "local", "timeout": 300000, "enabled": true,
    "command": ["npx", "mcp-remote", "https://mcp.YOUR-DOMAIN/mcp", "--transport", "http-only",
                "--keep-alive", "--header-file", "<путь>/mcp-memory.headers"] }
  ```
  В `mcp-memory.headers` — одна строка `Authorization: Bearer <токен>`. `timeout` 300 с: «обобщи»
  длится до 4 минут. Навык — `agents/skills/memory/SKILL.md`.
- **Claude Code / Cursor**: HTTP-транспорт `https://mcp.YOUR-DOMAIN/mcp` с заголовком `Authorization: Bearer …`.
- **Клиент без заголовков (коннектор веб-чата)**: отдельный экземпляр (`memory_mcp_connector`, своя зона
  `Inbox/<имя>/`) по секретному пути `/c/<секрет>/mcp` — см. Caddy-пример. Секрет = пароль: хранить как пароль.
- **Агент на том же сервере (Hermes)**: внутри Docker-сети, без прокси: `http://memory_mcp_hermes:8765/mcp`.
  Подробнее — `runbook-hermes.md`.

Новый агент = новый экземпляр в `docker-compose.yml` (копия сервиса `mcp` с другим `INBOX_PREFIX`,
`AUDIT_LOG` и портом). Читают все одно и то же зеркало.

## 4. Эксплуатация
- Журнал операций: том `mcp-logs` (`audit*.log`, JSON lines) — кто, что, когда читал/писал.
- Обновление кода: `docker compose build mcp && docker compose up -d mcp bm25` (и все экземпляры агентов).
  Внимание: `docker restart` НЕ подхватывает новый образ/переменные — только `up -d` (пересоздание).
- Заметки поиска копятся в `Inbox/<агент>/Search/` — их можно периодически чистить вручную.

## Чего не делать
- Не публиковать порт 8765 наружу напрямую и не убирать проверку токена «на время».
- Не давать агентам один экземпляр на всех — зона записи должна быть своя.
- Не менять формат ответа `find_notes` и заметки поиска без согласия пользователя: это его интерфейс.
