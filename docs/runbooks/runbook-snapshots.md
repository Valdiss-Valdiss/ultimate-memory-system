# Runbook — Снапшоты ВМ и бэкапы

## Зачем

Полный откат сервера за минуты при аварии (проверено вживую). Компенсирует любые
«мистические» повреждения: волны удалений, битые конфиги, неудачные деплои.

## Правила

1. **Свежий снапшот перед любой массовой операцией** (миграции, переименования,
   пересборка зеркала, обновление стека).
2. **Снапшот живёт ~1 сутки** (Hostinger) — старый сам сотрётся; планируй.
3. Снапшот = полный образ ВМ: восстановление необратимо, ВМ блокируется ~30 мин.
4. До снапшота: пусть закончатся активные конвейеры (бэкфиллы) — или смирись, что
   их изменения в снапшот не попадут (они идемпотентны).

## После восстановления из снапшота (чек-лист)

1. `systemctl is-active docker memory-livesync-reconcile`; контейнеры подняты;
2. SSH host key сменился: `ssh-keygen -R <ip>` (иначе connection refused/conflict);
3. Возможен транзиентный read-only FS в первые минуты — ретраи;
4. Устройства (ПК/телефон) — re-setup: Delete local database → Fetch from remote;
5. Проверить, что телефон был донором: если у телефона были несинхронизированные
   правки — сначала дать ему выгрузить, потом re-setup.

## Бэкапы на стороне ПК

- Ночной бэкап vault (Duplicati/Kopia/restic/cron tar) — обязателен;
- Хранить минимум 7 точек (последние сутки — чаще всего нужны);
- IndexedDB плагина LiveSync (`%APPDATA%\obsidian\IndexedDB`) — копировать перед
  аварийными операциями (там логи плагина).

## Серверные бэкапы

- Конфиги и secrets → в каталог бэкапов на ВМ (вне git);
- CouchDB: файлы БД входят в снапшот ВМ; для частых точек — `_replicate` в
  запасную базу/сервер (опционально).
