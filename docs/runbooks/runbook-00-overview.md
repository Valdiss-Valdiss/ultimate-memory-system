# Runbook 00 — обзор и порядок внедрения

## Как всё связано (кратко)

Три места: **VPS** (сервер, Docker — «мозг» и хранилище синхронизации), **ПК**
(Obsidian + конвейер импорта), **телефон** (только Obsidian-синк). Всё общается через
CouchDB (E2E-шифрованная синхронизация LiveSync) и Telegram.

Два независимых входа данных:
1. **Бот-конвейер (VPS)** — быстрый: ботов-вотчер кладёт посты в зеркальную копию vault,
   CLI-цикл выливает их в CouchDB → устройства.
2. **ПК-конвейер (user-session)** — полноценный: hourly-задача догоняет посты,
   скачивает вложения, обогащает (OCR/транскрипты/резюме), раскладывает по папкам.

Оба потока не конфликтуют: бот кладёт копии во входную папку (Inbox/…/Telegram/<канал>),
часовой триаж раскладывает их в целевые папки vault.

## Порядок внедрения (для агента)

```
0. Сбор требований: какой хостер, ОС ПК, Obsidian есть?, каналы пользователя.
1. VPS: docker → couchdb → qdrant/tei/docling → tg-bot → indexer (runbook-vps-setup.md)
2. ПК: Obsidian → LiveSync → E2E-vault → re-setup устройств (runbook-obsidian-livesync.md)
3. Telegram: bot-токен, user-session, каналы, folders.yaml (runbook-telegram-import.md)
4. ПК-конвейер: часовая задача + стражи + validate (pc-scripts/README.md)
5. Приёмка: validate всё зелёное → тестовый пост → заметка в папке → готово.
6. Периодически: снапшоты, STATUS, чистка очередей (runbook-snapshots.md)
```

## Чего НЕ делать никогда

- Не хранить E2E-парольную фразу на сервере.
- Не запускать два python-процесса с одной Telegram-сессией.
- Не делать массовые удаления/переименования без снапшота и подтверждения юзера.
- Не менять порядок шагов CLI-цикла: `sync → sync → mirror` (mirror — ПОСЛЕДНИЙ,
  это самовосстановление от deletion-волн; инциденты 15–16.09 доказали).
- Не лечить Telegram 429 ретраями — только охлаждением (floodguard).

## Словарь (для юзера)

- **Vault** — папка Obsidian с заметками (шифруется целиком).
- **Зеркало** — открытая текстовая копия vault на сервере (нужна для поиска/ИИ).
- **E2E** — end-to-end шифрование: сервер хранит шифроблоки, читает только устройство.
- **Бэкфилл** — дозаполнение старых заметок вложениями/описаниями.
- **Триаж** — раскладка заметок по папкам.
