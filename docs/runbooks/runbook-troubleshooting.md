# Runbook — Быстрые рецепты по симптомам (troubleshooting)

Формат: «видишь X → делай Y». Все рецепты проверены на проде. Если симптома нет в
списке — собери факты (логи, validate), открой соответствующий рунбук.

## Симптомы на стороне ПК

### Obsidian плагин предлагает «Reset database»
→ Не подтверждать вслепую. Скриншот агенту. Обычно безопасен только после
подтверждённого отбоя сервера (см. runbook-obsidian-livesync.md).

### Заметки не появляются на телефоне
1. Телефон синкнул? (открой Obsidian, дождись синка)
2. После ребилда сервера — телефону нужен re-setup (fetch), иначе репликация
   пытается залить весь граф (часы);
3. Заметки в базе? (CouchDB doc_count растёт; проверь входную папку зеркала)

### Бэкфиллы не запускаются
1. Obsidian открыт? (guard запрещает внешние записи при закрытом)
2. floodguard-маркер не активен? (tg_cooldown_until.txt)
3. Guard-скрипт запускает python напрямую (не через wscript!) — см. windows-quirks §2
4. stderr-файл показывает причину (должен быть всегда перенаправлен!)

### Бэкфилл «висит» на одной цели часами
1. Известный паттерн: таймауты скачивания больших медиа (30–80 мин);
2. Проверить stderr-файл (есть traceback?);
3. Если цель не критична — консервация: добавить в заметку маркер «не обработан»
   (только по решению юзера).

### «database is locked» на Telegram-сессии
Два клиента. Найти второй процесс (`Get-CimInstance Win32_Process ... python`),
убить/дождаться. Встроенный yield в pc_catchup обычно предотвращает.

### 429 / InvalidBufferError петля
floodguard должен перехватить. Если процесс старый (до фикса) — убить, дать
охлаждение 60+ мин, перезапустить. НЕ ретраить.

## Симптомы на сервере

### CouchDB unhealthy в docker ps
Ложная тревога (healthcheck без авторизации). Проверить фактически:
`curl -u user:pass localhost:5984/_up` внутри контейнера.

### doc_del_count растёт лавиной
Deletion-волна! (runbook-deletion-waves.md). Немедленно: остановить источники
записей, проверить порядок CLI-цикла (mirror LAST), откат снапшота.

### Зеркало отстаёт от vault
Цикл CLI активен? Лог `/tmp/reconcile-cli.log` (через /proc у PrivateTmp-сервиса).
Ищем «Synchronisation completed: N/N» — если N меньше ожидаемого — см. runbook-00.

### Семантический поиск не находит новое
Индексатор ходит циклами (sleep 300); проверь `docker logs memory_indexer`;
после больших массовых изменений индекс перестраивается сам (ETA часы).

## Симптомы сети/SSH

### «banner exchange… Connection aborted» в скриптах
Боты заполняют очередь SSH (runbook-ssh-hygiene.md): правила iptables + whitelist IP.
Если всё ещё сыплется — проверить, что whitelist совпадает с текущим IP клиента
(DHCP мог сменить).

### После рестарта сервера SSH «connection refused»
Host key сменился (откат снапшота) — `ssh-keygen -R <ip>`; либо sshd не поднялся —
через хостинг-консоль проверить `systemctl status ssh`.

## Метрики здоровья (сверка одним взглядом)

```bash
# ПК
Get-Process Obsidian (запущен), python (один процесс конвейера)
# сервер
doc_count / doc_del_count; контейнеры Up; лог CLI без Error
# vault
число .md ПК == числу .md зеркала (±few)
```
