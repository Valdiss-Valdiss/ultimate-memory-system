# Runbook — Волны удалений (массовые удаления vault): диагностика и защита

> Этот рунбук — результат двух реальных аварий (массовые удаления vault на устройствах).
> Прочитай целиком, если увидел: «vault почти пуст», «счётчик удалений растёт»,
> «заметки исчезают на нескольких устройствах».

## Симптом

- Vault на ПК вычищен почти целиком (выживают единичные свежезаписанные файлы);
- CouchDB получает `deleted:true` волной; зеркало тоже вычищено;
- Телефон/другие устройства повторяют удаление.

## Доказанный механизм (как это происходит)

1. Заметки массово переименованы/пересобраны → зеркало отстало;
2. sync-шаги CLI-цикла применяют CouchDB-пометки `deleted:true` к зеркалу
   **без** защиты newer-wins (она есть только у mirror-шага);
3. Цикл заканчивается вычищенным зеркалом → deletion-волна уезжает на устройства;
4. Выживают только файлы, изменённые ПОСЛЕ прихода пометки (конфликт-логика
   «новее выигрывает»).

## Фикс (обязателен в конфигурации)

**Порядок шагов CLI-цикла: `sync(in) → sync(out) → mirror (ПОСЛЕДНИЙ)`.**

Mirror-шаг с newer-wins отклоняет ошибочные deletion-флаги и восстанавливает зеркало
в конце каждого цикла → волна превращается в самооткат (в логе: сотни
«SKIP newer-wins: … (db-only-deleted)»). Менять порядок нельзя.

## Немедленные действия при живой волне

1. **Не паникуй и не подтверждай плагиновые диалоги** («Reset database» — только по скриншоту).
2. Останови источник записей (бэкфиллы/renamer) — но НЕ Obsidian, если там живые правки.
3. Сверь счётчики: vault ПК, зеркало, CouchDB (doc_count/doc_del_count);
4. Откат: снапшот ВМ (если есть свежий) → затем re-setup устройств
   (runbook-obsidian-livesync.md);
5. Если донор данных — телефон (офлайн во время волны): сначала обычный синк
   телефона (выгрузит патчи), потом re-setup.

## Дедупликация после массовых rename

Признак: одно содержимое под двумя именами (старое авто-имя + новое осмысленное).

Процедура (проверена, 119 шт за раз):
1. Пары определить по `channel_id + msg_id` (frontmatter);
2. Контент пар сравнить байт-в-байт (нужен merge если отличается — сначала merge!);
3. Удалить старые имена через **CLI rm** (сервер): `livesync-cli-once.sh rm "<path>"`
   — полный круг: DB → зеркало удалит файл → плагины устройств удалят копии;
4. Проверка после: `doc_del_count`, счётчики vault/зеркала, отсутствие воскрешений.

## Предохранители (должны быть всегда включены)

1. Mirror-last self-healing (сервер сам откатывает волны);
2. Deletion Propagation → корзина Obsidian;
3. Снапшот ВМ перед массовыми операциями (+ дAILY бэкап vault на ПК);
4. Правило: массовые rename только при закрытом бэкфилле; дедуп после сходимости.

## Триггер самого плагина (если волна родилась на устройстве)

Может не вскрыться (логи плагина гибнут). Компенсации — перечисленные предохранители.
При следующем окне: включить Log to file у плагина, бэкапить IndexedDB до остановок.
