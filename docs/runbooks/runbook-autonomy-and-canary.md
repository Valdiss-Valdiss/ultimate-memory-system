# Runbook - Автономность и канари здоровья

> Цель: система сама поднимается после сна/обрыва сети/смены IP и **сама
> сообщает**, что сломалась. Проверенные рецепты, откат указан.

## 1. Канари (heartbeat всей системы)

`pc-scripts/health_canary.py` + задача Windows «Memory Health Canary» (раз в
час). Проверяет и пишет компактный отчёт в заметку `Inbox/AI/Status/health.md`
(в vault её видно в Obsidian и находит поиск; в Telegram система ничего не
пишет — только читает).

| Строка отчёта | Норма | Если нет |
|---|---|---|
| Публичный IP | IP вашей машины | сетевые сервисы недоступны |
| SSH до VPS | ok | IP не в whitelist → `runbook-ssh-hygiene.md` |
| LLM-ключ | жив (метка ключа) | 401/429 → `runbook-llm-keys.md` |
| CouchDB (HTTPS) | ok (200/401) | сервер недоступен |
| Очереди бэкфилла | фото=0 док=0 | идут работы; если «вечно» — см. §4 |
| Бэкфилл (свежесть логов) | минуты | процесс завис или не запущен |
| Telegram-догон | время последнего прогона | сессия/сеть |
| Duplicati | время последнего бэкапа | бэкапы не идут |

Запуск вручную: `python pc-scripts/health_canary.py` (лог — `canary.log`).

## 2. Healthcheck CouchDB (обязателен!)

```yaml
healthcheck:
  test: ["CMD-SHELL", "curl -s -o /dev/null -w '%{http_code}' http://localhost:5984/_up | grep -Eq '^(200|401)$'"]
```

Почему не `curl -f /_up`: CouchDB отвечает 401 (нужна авторизация), docker
считает контейнер «unhealthy», внешний autoheal (у хостера) начинает его
перезапускать — синк рвётся, клиенты видят «Failed to fetch».

Проверка: `docker inspect memory_couchdb --format '{{.State.Health.Status}}'`
→ `healthy`.

## 3. Авто-whitelist (переживает смену VPN)

См. `runbook-ssh-hygiene.md`. Суть: канари публикует IP → `sync-whitelist.sh`
(cron */10) добавляет ACCEPT-правило → старые IP вычищаются (TTL 7 дней).

## 4. Вечные цели в очереди бэкфилла

Если `photos=NN` не уменьшается: смотрите в логе `pc-scripts/photos_backfill.log`
строки `[patch-skip]` — они печатают причину. Типовые причины и что делать:

- «фото недоступны в Telegram (пост удалён)» — файла нет и не будет: помечается
  нейтрально, позиция закрывается.
- «документ не найден в посте» — вложение было удалено/не загрузилось.
- Ошибка `TimeoutError` при загрузке — сеть; позиция уйдёт в следующий прогон.
  Для крупных файлов поднимите `MAX_DOC_DOWNLOAD_MB` (по умолчанию 700).

## 5. Порядок восстановления после сбоя

1. `python publish/../validate/validate_vps.py` и `validate_pc.py` — что красное.
2. Сервер не отвечает → проверить `docker ps` (все контейнеры Up?) и диск.
3. ПК-цепочка не идёт → проверить, что Obsidian запущен и LiveSync в норме
   (`↑0 ↓0`), затем задача «Memory Catchup Hourly» (раз в час, `StartWhenAvailable`
   добирает пропущенные прогоны после сна).
4. Запустить канари вручную и посмотреть отчёт.
