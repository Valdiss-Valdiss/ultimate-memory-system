# SECURITY.md — ключи, пароли и данные

## Модель секретов

| Секрет | Где хранится | Что открывает | Утечка означает |
|---|---|---|---|
| Ключ SSH (id_ed25519) | только ПК пользователя | вход на сервер (user без root) | доступ к серверу как этот user |
| Root-пароль VPS | хостинг-панель (для консоли) | полный контроль ВМ | полный контроль ВМ |
| API_ID / API_HASH (Telegram) | `.env` на сервере и ПК | приложение Telegram | спуфинг приложения (аккаунт не угоняется) |
| BOT_TOKEN | `.env` на сервере | управление ботом | чтение постов каналов, управление ботом |
| Ключи LLM (LLM_KEY, Deepgram, TranscriptAPI) | `.env` | вызовы сервисов | трата квот |
| **E2E-парольная фраза vault** | **ТОЛЬКО устройства пользователя** | расшифровка vault | чтение всех заметок |

## Железные правила

1. **E2E-парольная фраза никогда не хранится на сервере.** Сервер не должен уметь
   расшифровывать vault. Если увидел passphrase в файлах сервера — инцидент, удаляй.
2. **Значения секретов никогда не печатаются** в логи, чат, отчёты. Проверка наличия —
   только по именам переменных.
3. `.env` — права 600 (только владелец), никогда не коммитится (см. `.gitignore`).
4. Ключ-файлы (SSH, Telegram-сессии) — никогда не копируются в репозиторий,
   облако, переписку. Они не передаются по сети (протокол не пересылает приватный
   материал), но вирус на ПК может их прочитать.
5. Парольный вход SSH на сервере — отключён (только ключи). Root — только через
   хостинг-консоль.

## Что попадает в этот репозиторий

- Код и документация — да.
- `.env.example` с ПОДСТАНОВОЧНЫМИ значениями (`changeme`) — да.
- Реальные `.env`, `channels.json`, `folders.yaml`, `session/`, `state/`, логи — **нет**.
  Все они в `.gitignore`.
- Примеры данных (`channels.example.json`, `folders.example.yaml`) — вымышленные
  значения, без реальных названий каналов и ID.

## Сервер памяти для ИИ-агентов (memory-MCP)

- Сервер читает **весь** расшифрованный vault. Открыть его наружу без авторизации = отдать заметки
  любому сканеру интернета. Доступ снаружи — только через реверс-прокси с `Authorization: Bearer <токен>`
  (`vps/caddy/memory-mcp.caddy.example`); порт сервера слушает только localhost/внутреннюю сеть.
- Токен и секретный путь коннектора — как пароли: в отдельном файле `chmod 600`, вне git и вне
  конфигов агентов (opencode получает заголовок из файла `--header-file`). Секретный путь не пишется в лог прокси.
- Каждый агент — свой экземпляр сервера со своей зоной записи `Inbox/<агент>/` и своим журналом
  операций; проверка зоны — в коде сервера (защита от `..` и абсолютных путей).
- Ключи LLM для расширения запроса и «обобщи» — в файле `vps/secrets/mcp-llm-key` (не в `.env`, не в git).
- Внимание: и запросы агента, и найденные заметки уходят выбранному LLM-провайдеру (расширение запроса —
  только текст запроса; «обобщи» — тексты найденных заметок). Для чувствительных данных используйте
  провайдера, которому доверяете, или отключите эти функции (`EXPAND_MODELS=` пусто).

## Проверка на утечку перед публикацией

```bash
grep -rniE "api_id|api_hash|bot_token|passphrase|t\.me/c/[0-9]" --exclude-dir=.git .
```
Найденные совпадения в коде — это чтение переменных окружения (ок), литеральные
значения — удалить немедленно.

## Политика публикации (что НЕ попадает в репозиторий)

Репозиторий публичный. В него попадает **только** обезличенный код и документация.
Запрещено публиковать:

- ключи, токены, пароли, `.env`, `auth.json`, файлы сессий Telegram (`session/`);
- реальные IP-адреса, домены, почтовые адреса, имена каналов/папок и названия
  заметок пользователя;
- фрагменты vault, логи, отчёты по личным данным.

Перед публикацией прогоняется **блокирующий скан-гейт** (в этом репозитории
такого нет — он в рабочем проекте автора): он ищет реальные IP, домены, ключи
(`oc_sk_*`, `sk-*`, bot-токены, base64-блобы), chat-id, ссылки `t.me/c/...`,
почту, пути с именем пользователя и запрещает выпуск при любой находке.

Проверка вручную (минимум):

```bash
grep -rInE "([0-9]{1,3}\.){3}[0-9]{1,3}|oc_sk_|sk-[A-Za-z0-9]{16,}|t\.me/c/[0-9]+|@[A-Za-z0-9.-]+\.[A-Za-z]{2,}" . | grep -v CHANGE-ME
```

Обезличивание: `memory@CHANGE-ME-server-ip`, `C:\Users\<user>\...`,
`couchdb.YOUR-DOMAIN`, `id_ed25519`, `YourHomeIp` — такие плейсхолдеры
допустимы.

## SSH-доступ и rate-limit (почему порог 30, а не 9)

Парольная аутентификация в sshd **выключена** (доступ только по ключу), поэтому
лимит «новых соединений» защищает не от подбора пароля, а от шума ботов,
который забивает очередь неаутентифицированных соединений (MaxStartups) и рвёт
легальные сессии. Порог 30/60 с выбран с запасом: машина пользователя может
выходить в сеть через VPN с разными адресами. Белый список IP держится
автоматически (канари публикует текущий IP → `sync-whitelist.sh` добавляет
правило), старые адреса вычищаются по TTL.


## Аварийный доступ

- Веб-консоль хостингера — вход в ВМ мимо SSH (страховка при поломке SSH).
- Снапшот ВМ — откат состояния целиком (живёт ~1 сутки).
- E2E: если потеряна парольная фраза — данные невосстановимы НИКЕМ. Храните её
  в менеджере паролей.
