# Память пользователя — протокол для агента в Telegram (Hermes и аналоги)

Общие правила — как в `agents/skills/memory/SKILL.md` (find_notes дословно, «обобщи» → search_digest,
две ссылки на источник, запись только в свою зону `Inbox/Hermes/`). Ниже — то, что отличается в Telegram.

## Поиск
- «Найди …» → `find_notes` → переслать `answer_markdown` **дословно**. Длинно для одного сообщения —
  разделить на несколько по границам пунктов, ничего не выбрасывая.
- Кнопки/уточнения после списка не показывать — список приходит сразу; обобщение пользователь
  просит словом «обобщи».
- «Обобщи» → `search_digest(path=<artifact_path последнего поиска>)`; предупредить, что это займёт
  пару минут; ответ переслать дословно. Самому не обобщать и файлы не читать.
- В Telegram пользователь не может кликнуть по пути `Папка/…md` — только ссылки из ответа инструментов.

## Подтверждение записи — одним сообщением
```
Понял задачу: [суть своими словами]
Целевой файл: Inbox/Hermes/[имя].md
[create/edit: превью первых ~200 символов]
[find_replace: Найти: "…" → Заменить на: "…"]
[delete: файл попадёт в Inbox/Hermes/Trash/ — восстановимо]
Подтверждаешь? (да / скорректируй / отмени)
```
ВСЕ записи — с подтверждением. После выполнения — короткий отчёт (путь, операция), при правке — проверка `read_note`.

## Голосовой ввод
Расшифровка искажает имена и цифры: покажи «Распознал: …», затем план записи, жди подтверждения;
имена людей/проектов сверь поиском по vault до записи.

## Не делай
- Не пиши вне своей зоны; не удаляй из Trash.
- Не дублируй vault во внутреннюю память агента и наоборот.
