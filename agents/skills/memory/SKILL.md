# Память пользователя (Memory System)

Vault — заметки пользователя в Obsidian: посты из его Telegram-каналов (с резюме, транскриптами,
OCR) и ручные записи. Доступ — инструменты сервера memory-MCP. Читать можно весь vault,
писать — только в свою зону `Inbox/<агент>/` (сервер сам отклонит запись в другое место).

## Когда использовать
- Вопрос зависит от сохранённого: «найди в заметках», «что я знаю про X», «что мы решали», «мои идеи/клиенты».
- «Запомни / сохрани / добавь в заметки / обнови заметку».
- НЕ для общих знаний без привязки к записям пользователя.

## Ответ на «найди / что у меня есть / что я знаю про …» — только через `find_notes`
1. `find_notes(query=<тема словами пользователя>)` — один вызов. Убери только служебные слова
   («найди», «в заметках»). Синонимы и перевод НЕ добавляй — сервер сам расширяет запрос, одинаково
   для всех агентов. Просят новое/свежее → `fresh=true`.
2. Перешли поле `answer_markdown` **дословно и целиком**: до 20 заметок, у каждой
   «[имя заметки](пост в Telegram) · [открыть в Obsidian](…)» и описание; в конце ссылка на полный
   список и подсказка «обобщи». Не сокращай, не переставляй, не меняй текст ссылок.
3. Своё обобщение в этот ответ НЕ добавляй.
4. «Обобщи» / «резюме по всем найденным» → `search_digest(path=<artifact_path последнего поиска>)`.
   Обобщение по ВСЕМ найденным заметкам пишет сервер (1,5–4 мин) и сам дописывает его в заметку
   поиска. Перешли его `answer_markdown` дословно.
5. Подробнее про одну заметку → `read_note(path)` и ответ по её содержанию с теми же двумя ссылками.

Формат ответа — дизайн пользователя: менять только после его явного «да».

## Ссылки на источники
- Две ссылки рядом: `[имя заметки](telegram_url) · [открыть в Obsidian](obsidian_web)`; текст первой —
  точное имя файла заметки, как в Obsidian, с датой (без `.md`).
- `obsidian_url` (`obsidian://…`) — для агентов на ПК; часть приложений вырезает такие ссылки —
  тогда `obsidian_web` (https-переходник).
- Нет `telegram_url` (ручная заметка) → имя заметки текстом · `[открыть в Obsidian](…)`.
- Ссылки — только из полей ответа инструментов. Голые пути не давай. Заметки из `Inbox/*/Search/` — не источники.

## Прочее чтение
- Точные слова, имена, ID → `search_notes`. Свой анализ по папке/каналу → `semantic_search(folder=…, channel=…)`.
- Прежде чем сказать «ничего нет» — 2–3 варианта запроса.

## Запись (только своя зона)
Классифицируй действие перед каждым вызовом:
- **READ** — выполнять сразу.
- **WRITE_SINGLE** — показать путь + превью (~200 символов) и **дождаться подтверждения**.
- **WRITE_AMBIGUOUS** — сначала один уточняющий вопрос, потом план.
- **BATCH** (много файлов) — полный план со списком файлов, что обратимо/необратимо → явное «да».

Правила:
- Не пиши в файл, который не прочитал в этой сессии.
- Новая заметка: имя `тема-контекст-ГГГГ-ММ-ДД.md`; frontmatter: `type`, `created`, `updated`,
  `source: <агент>`, `status: draft`, `tags`; пустые ключи не писать. Если видна целевая папка
  пользователя — `folder: <путь>` (он разложит при разборе Inbox).
- `edit_note` — минимальная операция (`append`/`prepend`/`find_replace` с точным старым текстом/`replace_section`), затем проверь `read_note`.
- `move_note` — только внутри зоны; wikilinks не обновляются — предупреди.
- `delete_note` — мягкое удаление в `Inbox/<агент>/Trash/` (`confirm: true` после «да»); чистка Trash — только человек.
- Исключение из подтверждения: дописывание в свою заметку поиска.

## Ошибки
Не повторяй молча с другими параметрами: покажи ошибку дословно, объясни, что пытался сделать,
спроси, как продолжить. Отказ сервера по зоне — правило, а не сбой. Один повтор при сетевом обрыве — норма.

## Границы
- Не храни в vault секреты, ключи, токены.
- Изменения доезжают до устройств через синхронизацию (~30–60 с).
- Отвечай на языке пользователя.
